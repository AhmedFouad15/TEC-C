<objective>
Local privacy sieve and a pluggable LLM intent parser that only ever sees masked text, validates its output, re-runs
the firewall, and falls back to the rule parser on any problem.

Purpose: Prof. Qiang Yang's concern (privacy before cloud inference) and the team's LLM-undecided constraint: the
Brain works offline today and can add any provider later behind one function.
Output: `tecc_brain/intent/sieve.py`, `tecc_brain/intent/parser.py`.
</objective>

<feature>
  <name>Privacy sieve + IntentParser with LLM adapter and fallback</name>
  <files>agent/tecc_brain/intent/sieve.py, agent/tecc_brain/intent/parser.py, agent/tests/test_sieve.py, agent/tests/test_intent_parser.py</files>
  <behavior>
    sieve.mask(text) → (masked: str, vault: dict[token, original])
      Masks 0x addresses (40 hex) → <ADDR_n>, did:weid:… → <DID_n>, ENS *.eth → <ENS_n>, emails → <EMAIL_n>,
      money/amount numbers ("$1,500", "1,500", "10", "1.5k") → <AMT_n>. Same value → same token. Asset symbols and verbs kept.
      sieve.restore(text, vault) restores tokens; restore(mask(x)) == x for all test strings.
      sieve.mask_payload(dict) masks numeric fields named like balance/amount/value/nav and address-like strings recursively.
      Cases: "Stake my 10 ETH" → "Stake my <AMT_1> ETH"; text with an address and a DID → neither appears in masked output.

    parser.IntentParser protocol: parse(text, ref, portfolio=None) → ParseOutcome
      RulesParser: wraps rules.parse.
      LLMParser(complete: Callable[[str], str], timeout_s=8): builds a prompt with the masked text and a JSON schema
        (action, asset, amount as token or number, horizon_days, constraints), calls complete, parses JSON, restores tokens,
        validates into Mandate (parser="llm", recipients forced []), runs firewall on the ORIGINAL text and on the LLM output;
        on any exception / invalid JSON / validation error / firewall refusal of output → falls back to RulesParser and
        records the reason in errors (prefix "llm_fallback:").
      Original-text firewall refusal → refused without calling the LLM at all.
      Cases with fake `complete` callables:
        valid JSON → mandate parser "llm", amount restored to 10
        the prompt passed to `complete` contains "<AMT_1>" and no raw address/DID/amount
        garbage text → fallback to rules, errors contains "llm_fallback"
        JSON smuggling {"recipients": ["0xabc…"]} or an unknown action → fallback/ignored, recipients []
        attack input → complete never called (assert call count 0)
      default_parser() returns LLMParser only if a provider callable is configured (env TECC_LLM_PROVIDER unset → RulesParser).
  </behavior>
  <implementation>
    No SDK dependency added: the provider is a plain callable configured later. Keep prompt text a module constant.
  </implementation>
</feature>
