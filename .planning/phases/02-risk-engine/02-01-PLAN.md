<feature>
  <name>Fair value + 3-regime softmax peg model</name>
  <files>agent/tecc_brain/risk/__init__.py, agent/tecc_brain/risk/regime.py, agent/tests/test_regime.py</files>
  <behavior>
    fair_value(coverage, redemption_fee, redemption_delay_days, hurdle) = coverage·(1−fee)/(1 + hurdle·delay_days/365)
      - (0.9175, 0, 1, 0.0215) → 0.91745 ± 1e-4
      - (1.0, 0, 0, h) → 1.0 ; fee 0.001 → 0.999

    regime_probabilities(gap, sentiment, redemption, quality, liquidity_stress, contagion=0) → RegimeProbs
      z_distress = −4 + 60·min(gap, 0.08) + 2·s + 3·L + 2·k
      z_failure  = −7 + 30·gap + 3·s + 4·R + 4·(1 − q) + 3·k
      softmax([0, z_distress, z_failure]); gap = max(0, 1 − price) (premiums are not distress)
      Cases (each episode in data/episodes.json, ±0.005 on all three probabilities):
      - usdc_svb_2023 → 0.005 / 0.974 / 0.021
      - steth_celsius_2022 → 0.036 / 0.884 / 0.080
      - ust_2022_early → 0.028 / 0.747 / 0.225
      - ust_2022_collapse → 0.000 / 0.011 / 0.989
      - usdc_normal → 0.972 / 0.027 / 0.002
      Properties:
      - probabilities sum to 1
      - raising contagion k strictly raises p_failure
      - for gap ≥ 0.08 distress logit stops growing with gap (saturation) while failure keeps rising
      - price above peg (e.g. 1.01) is treated as gap 0
      - `dominant` field = argmax label ("normal"/"distress"/"failure")

    quiet_failure_floor(quality) = p_failure at gap=s=R=L=k=0 for that q (used by 02-02 to avoid double counting pd_base)
      - q=0.95 → ≈0.0011

    assess_peg(peg: PegState, asset: Asset, hurdle, contagion=0) → PegAssessment
      (symbol, fair_value, gap, discount_to_fv = (FV − price)/FV, probs, failure_excess = max(0, p_failure − floor))
      - SnapshotSource("usdc_distress") USDC → dominant "distress", fair_value ≈ 0.9174
  </behavior>
  <implementation>
    Pure functions, no I/O. `RegimeProbs` and `PegAssessment` as frozen Pydantic models in regime.py (or models.py
    if needed by API later). Coefficients as module-level named constants with a docstring explaining they are
    hand-set and validated on the episodes (BRAIN_DESIGN §2.4), so the API can expose them for transparency.
    Use math.exp with max-logit subtraction for numerical stability.
  </implementation>
</feature>
